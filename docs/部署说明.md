# 运行和部署说明

## 本地开发

Node.js 22 LTS 推荐；项目兼容 Node.js 18.18 以上。执行 `npm ci` 和 `npm run dev`，打开 `http://127.0.0.1:5173`。不要只打开 index.html，也不要通过 `vite preview` 期待自动运行后端。

启动脚本读取**进程环境变量**，不自动解析 `.env`。`.env.example` 是字段说明。Docker Compose 可以使用自己的 `.env` 插值机制，但需要自行把字段加入 compose.yml。

## 本机生产构建

```bash
npm ci
npm run build
npm start
```

打开 `http://localhost:3001`。Express 提供静态页面与 API，子路由刷新由 SPA 回退处理。

PowerShell 设置自定义端口和数据目录：

```powershell
$env:PORT = '3001'
$env:DATA_DIR = 'D:\flowdesk-data'
npm start
```

## Docker

已提供多阶段 Dockerfile 和 compose.yml。安装 Docker 的环境中：

```bash
docker compose up --build -d
```

打开 `http://localhost:3001`。命名卷 `flowdesk_data` 保存数据库和文件；重建容器不会清空命名卷。当前执行环境如果没有 Docker，应在目标服务器先验证镜像构建。

默认 Compose 配置是演示模式，不代表私有生产配置。

## 私有部署

首次启动前使用**全新且可写的 DATA_DIR**，设置：

| 环境变量 | 用途 |
| --- | --- |
| PORT | 服务端口，默认 3001 |
| DATA_DIR | 持久化数据目录，默认 ./data |
| DEMO_MODE=false | 禁用首次演示数据和快捷登录入口 |
| ADMIN_PASSWORD | 首次建立 admin 的密码，至少 12 位 |
| COOKIE_SECURE=true | HTTPS 环境下只通过安全连接发送会话 Cookie |

只改变 DEMO_MODE 不会删除已有账号或历史数据；已有演示数据目录不能直接当作安全的私有部署初始化。

用 Nginx/Caddy 等反向代理提供 HTTPS，保留 Host 请求头，上传请求体至少允许 2 MB 分片和 multipart 开销。示例 Nginx 关键配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 3m;
}
```

数据库与上传目录都应放到持久化磁盘。使用云容器的临时磁盘会在实例替换时丢失数据。GitHub Pages 等纯静态托管不能承载本项目完整后端。

## 当前运行规模与风险

- 服务端必须单进程运行，不能把多个实例同时指向同一个 sql.js 数据文件。
- 数据库驻留内存，写入时导出整个文件；适合演示和轻量实例。没有高并发负载测试结果。
- 登录会话有效期 8 小时。错误登录按 IP 限制 15 分钟内 15 次；代理后 IP 识别策略需要针对实际部署验证。
- 单文件限制 200 MB，每份申请最多 10 个附件；当前没有账号总配额、上传任务过期或磁盘自动清理。
- 上传内容只允许下载，没有杀毒、自动识别执照或内容审核。
- 本地草稿在浏览器内保存，不加密、不跨浏览器同步；退出不会删除本机对应账号的草稿。
- MD5 用于续传和误码检测，不适合作为防恶意碰撞的密码学认证。
- 操作日志是业务留痕，没有独立不可篡改审计存储。

## 备份与数据维护

备份应同时包含 `flowdesk.sqlite` 和 `uploads/`。建议先停止实例，再复制完整数据目录，避免数据库与文件在不同时间被备份。恢复到新的可写目录后，重新设置 DATA_DIR。

没有提供自动清空工作空间按钮，避免误删数据。为一次性演示重新生成数据时，应使用一个新的 DATA_DIR，保留原目录备份。

## 自动化验证

`npm test` 执行身份验证、数据隔离、跨字段校验、流程与版本冲突、上传续传与合并、账号停用等测试。`npm run build` 检查前后端类型并输出生产包。

GitHub Actions 在 Linux/Node 22 环境中构建项目并运行 Playwright，对生产服务做角色导航、申请退回重提、草稿恢复、暂停后刷新续传、秒传、成员管理与 390px 手机视口检查。报告与失败截图在工作流 artifact 中。
