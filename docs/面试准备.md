# 面试讲解与追问

## 30 秒介绍

“我做了一个企业申请与审核工作台，主要解决企业服务、采购、资质材料在多个角色之间流转的问题。前端用 Vue 3、TypeScript、Pinia，后端用 Express 和 SQLite。重点做了动态路由和接口权限、配置化联动表单、草稿恢复，以及大文件分片上传。可以现场用专员和审核员走一遍提交、退回、修改和通过。”

## 先演示业务，再讲技术

先用专员创建一份采购申请：选择个人主体、预算 25,000 元、补充预算依据、时间和说明。刷新后恢复草稿，提交。再用审核员退回，说明需要补充配置；专员重提，审核员通过。

接下来展示文件上传暂停/续传和秒传，最后对比角色菜单、列表预算列以及管理员日志。这样每一个技术点都有对应的业务理由。

## 高频追问

### 为什么前端路由和按钮权限不够？

用户可以绕过页面直接请求接口。因此服务器根据会话查询真实角色，并检查申请或文件是否属于当前用户。测试中普通专员请求用户管理返回 403，访问别人的申请和文件返回 404。

前端只是减少无效操作和改善体验。若只做 `v-permission`，不能称为完整权限系统。

### 为什么使用随机会话而不是把 JWT 放 localStorage？

项目采用服务端会话，方便权限变更和账号停用立即失效。Cookie 设置 HttpOnly，页面脚本无法直接读取。服务器检查写请求的 Origin，并使用 SameSite 限制跨站请求。

这不代表 XSS 被自动解决：恶意同源脚本仍可能代用户发请求，所以还需要内容转义、CSP、输入边界和避免任意 HTML 注入。Vue 文本插值默认转义，文件只作为附件下载。

### 配置化表单和普通组件封装有什么不同？

组件封装统一输入框；配置化表单进一步把字段结构、布局、选项和显示条件放到配置中。字段渲染器统一处理事件，业务规则共用函数。新的企业字段可以优先改配置，而不必复制页面。

本版没有做到完整 JSON Schema 标准或在线表单设计器。配置中使用 eq、gt 等白名单运算符表达显示条件，这个范围要讲清楚。

### 怎么避免异步校验返回顺序错误？

使用 AbortController。字段变化或发起新检查时取消旧请求；只有未取消请求可以更新错误状态。服务器在最终提交时再次校验，不相信前端之前返回的成功。

### 为什么草稿用 IndexedDB？

它是异步存储，适合结构化数据，避免频繁同步 localStorage 写入。本版按账号和申请隔离，600 ms 防抖，再通过 Promise 链顺序落库。刷新后提示恢复，减少静默覆盖。

本地草稿仅限当前浏览器；“保存草稿”按钮写入服务端，可以跨设备。提交成功后删除本地草稿。

### 文件暂停和断点续传到底保存了什么？

暂停取消网络请求；服务器保存已接收分片索引。恢复先重新初始化上传任务，再只传缺失分片。刷新后浏览器不能恢复原 File 对象，所以要求用户重新选择原文件，计算同一指纹找到原任务。

不能说后台一直自动上传，也不能说刷新后无需选择文件就能继续。

### 为什么哈希放 Worker？

读取和计算大文件可能占用主线程，Worker 可以保持页面交互。文件按 2 MB 逐片读取，不一次把整个文件 ArrayBuffer 放进内存。Worker 只是隔离计算，不会让哈希必然更快。

### 三个并发请求是怎么控制的？

当前文件有三个异步 Worker 函数，共享待上传下标游标。每个函数完成一片后领取下一片；多个文件顺序执行，因此总体不会因一次选择大量文件而无限增加并发。暂停时取消该文件的统一 AbortController。

### 为什么服务器还要计算哈希？

前端传来的哈希和成功状态都不可信。服务器校验分片大小与索引，再逐片合并并计算整体 MD5，检测传输误码。失败后清除错误检查点，允许重试。

MD5 存在恶意碰撞风险，所以不把它当作文件真实性或对抗恶意攻击的保证。未来可以换 SHA-256。

### 两个审核员同时点通过怎么办？

提交时带申请版本；服务器要求状态为 pending 且版本相同。第一个更新后版本加一，第二个请求返回 409。本项目单进程检查和写入不含异步等待；迁移到多进程应使用数据库条件更新及影响行数判断。

### 这套系统能扛多少并发？

没有做负载压测，所以不报未经测量的数字。当前 sql.js 会把数据库放在内存并在写事务后导出，本版适合演示和轻量单实例。真实规模扩张需要原生数据库、SQL 分页、上传配额和对象存储，再实际测量吞吐、延迟和内存。

### 有哪些实际排查过的问题？

- 开发代理改写 Host，导致正常登录被 Origin 校验拦截：明确配置 `changeOrigin:false`，保留同源请求头。
- Windows 的 Node 18 测试命令不展开通配符：脚本显式列出测试入口。
- sql.js 新版不导出 package.json：通过公开导出的 wasm 文件路径加载运行时。
- 隐藏文件输入框被全局输入宽度覆盖，造成手机横向溢出：为屏幕阅读器专用输入单独约束宽高。
- 本地草稿热更新后恢复，字段条件仍需正常联动；附加材料完成后不能因后续队列更新重新关联已经移除的附件。

## 面试前亲自理解的代码

1. `shared/domain.ts`：权限表、状态、业务校验。
2. `src/router.ts` 和 `src/main.ts`：动态路由与指令。
3. `src/pages/RequestEditor.vue`：字段校验、恢复和提交。
4. `src/stores/uploads.ts`：任务队列、分片并发、暂停与重试。
5. `server/app.ts`：资源隔离、审核冲突、上传检查与合并。

每个模块尝试改一个需求、制造一个失败并定位原因。能够现场解释和修改，比背诵架构文档更有说服力。
